Governança da tradução em sistemas de IA generativa: design de serviço e HCI para interações baseadas em prompts

Roc de Castro · 2026
Index Terms IA generativa engenharia de prompts governança da GenAI design de serviço sistemas sociotécnicos interação humano-computador

Abstract

A ascensão da Inteligência Artificial Generativa (GenAI) marca uma descontinuidade relevante na história da Interação Humano-Computador (HCI): a linguagem natural deixa de ser apenas meio de comunicação inter-humana e passa a operar como mecanismo primário de controle computacional e orquestração de serviços. Nesse paradigma, a qualidade do que se obtém de um modelo não é determinada exclusivamente por "capacidade" do modelo, mas também pela qualidade da instrução que conecta intenção humana a execução probabilística, isto é, pela engenharia de prompts.

No entanto, quando tratada predominantemente como habilidade textual ou competência individual, essa prática mostra-se insuficiente para sustentar escalabilidade, governança e responsabilização em sistemas sociotécnicos organizacionais. Este trabalho argumenta que a engenharia de prompts deve ser reformulada como um problema arquitetural e sociotécnico, no qual a governança da tradução assume papel central no uso organizacional de GenAI.

Propõe-se uma separação explícita entre Tradução (T) — camada governável na qual intenções são interpretadas, estruturadas e restringidas — e Execução (E) — a geração probabilística realizada por modelos de linguagem. A distinção permite analisar com maior precisão o que pode ser projetado, controlado e auditado em sistemas baseados em prompts, sem confundir decisões arquiteturais com variabilidade de output.

Para operacionalizar esse enquadramento, o trabalho apresenta dois instrumentos analíticos derivados: a Taxonomia de Prompt Orientada a Serviço (SOP) e o GenAI Service Blueprint, que classificam prompts por função no serviço e tornam visível a camada de tradução que media a relação entre usuários, organização e modelos. O argumento é ancorado em um estudo de caso observacional de um Cognitive Prompt Middleware (CPM) implementado como agente em ambiente corporativo, incluindo uma instância baseline (Prompt Assistant) e variações arquiteturais com diferentes níveis de fricção e governança.

Sem pretensão de prova causal, o caso demonstra a plausibilidade operacional de institucionalizar a tradução como camada governada, tornando explícitos trade-offs entre controle, autonomia e previsibilidade em serviços organizacionais baseados em GenAI.

5. Estudo de caso: Cognitive Prompt Middleware (CPM)

[Conteúdo a preencher]

Exemplo — System prompt do Prompt Assistant (instância baseline)

# Papel
Você é um assistente especializado em otimização de prompts para modelos de linguagem
de grande escala (LLMs). Seu papel é apoiar profissionais a estruturar, melhorar e
governar prompts utilizados em contextos organizacionais.

# Escopo
- Analise o prompt fornecido pelo usuário
- Identifique lacunas de especificidade, ambiguidades e riscos de output não determinístico
- Proponha uma versão estruturada com: papel, contexto, instrução, formato de saída
  e restrições
- Classifique o prompt na Taxonomia SOP (System / Orchestration / User / Meta / Validation)

# Restrições
- Não execute a tarefa descrita no prompt — apenas otimize a instrução
- Mantenha a intenção original do usuário; não substitua objetivos
- Sinalize quando um prompt solicitar capacidades além do escopo do modelo

# Formato de saída
Retorne um objeto JSON com os campos:
{
  "tipo_sop": "[classificação SOP]",
  "lacunas_identificadas": ["..."],
  "prompt_otimizado": "...",
  "justificativa": "..."
}

Exemplo — Output estruturado do CPM

{
  "tipo_sop": "User → otimizado para System",
  "lacunas_identificadas": [
    "Ausência de papel explícito para o modelo",
    "Formato de saída não especificado",
    "Nenhuma restrição de escopo definida"
  ],
  "prompt_otimizado": "Você é um analista de dados sênior. Dado o conjunto de dados
    CSV fornecido, gere um relatório executivo em português com: (1) principais
    tendências, (2) anomalias detectadas, (3) recomendações priorizadas. Formato:
    JSON com campos 'tendencias', 'anomalias', 'recomendacoes'. Limite: 500 palavras
    por campo.",
  "justificativa": "O prompt original ('analise esses dados') carecia de papel,
    formato e escopo. A versão otimizada reduz variabilidade de output e torna o
    resultado auditável."
}
